# Examples

Reference scaffolds for adding sections, blocks, and snippets to this theme.
**Every section/block in this repo follows this pattern**:

1. Define the schema in `src/schemas/{sections,blocks}/<name>.schema.ts` using
   `defineSection()` or `defineBlock()`.
2. Create the matching `.liquid` file in `sections/` or `blocks/` with an
   empty `{% schema %}{% endschema %}` placeholder.
3. Run `npm run schemas` (also runs as part of `npm run build`). The compiled
   JSON is injected into the placeholder.

Never edit the JSON inside `{% schema %}` by hand — it is overwritten on the
next build. The TS file is the source of truth.

---

## Section example

`src/schemas/sections/example.schema.ts`:

```ts
import { defineSection } from "../types.ts";

export default defineSection({
  // REQUIRED. Translation key from locales/en.default.json or a literal string.
  name: "t:names.example",

  // OPTIONAL. Wrapper tag rendered by the editor (defaults to "div").
  // Use `null` to skip the wrapper entirely.
  tag: "section",

  // OPTIONAL. CSS class on the wrapper.
  class: "example-section",

  // OPTIONAL. Restrict where the section can appear.
  // enabled_on: { templates: ["index", "product"] },
  // disabled_on: { groups: ["header", "footer"] },

  // OPTIONAL. Allowed child blocks. `@theme` = all theme blocks; `@app` = app blocks.
  // blocks: [{ type: "@theme" }, { type: "_divider" }],

  // OPTIONAL. Editor-configurable settings (typed in src/schemas/types.ts).
  // settings: [
  //   { type: "text",  id: "heading", label: "t:settings.heading", default: "Hello" },
  //   { type: "range", id: "padding", label: "t:settings.padding",
  //     min: 0, max: 100, step: 4, unit: "px", default: 24 },
  // ],

  // OPTIONAL. Default placements offered in the "Add section" picker.
  // presets: [{ name: "t:names.example" }],
});
```

`sections/example.liquid`:

```liquid
{% comment %}
  example: scaffold — populate as needed.
  Schema source: src/schemas/sections/example.schema.ts
  The {% schema %} block below is regenerated by `npm run schemas`.
{% endcomment %}

<section class="example-section">
  {% content_for 'blocks' %}
</section>

{% schema %}
{}
{% endschema %}
```

## Block example

`src/schemas/blocks/example.schema.ts`:

```ts
import { defineBlock } from "../types.ts";

export default defineBlock({
  // REQUIRED.
  name: "t:names.example",

  // OPTIONAL. Wrapper tag. Use `null` to skip the wrapper.
  tag: null,

  // OPTIONAL.
  // class: "example-block",

  // OPTIONAL — container blocks only. Allow nested blocks. Container blocks
  // should be filename-prefixed with `_` (e.g. `blocks/_example.liquid`).
  // blocks: [{ type: "@theme" }],

  // OPTIONAL.
  // settings: [
  //   { type: "richtext", id: "body", label: "t:settings.body" },
  // ],
});
```

`blocks/example.liquid`:

```liquid
{% comment %}
  example: scaffold — populate as needed.
  Schema source: src/schemas/blocks/example.schema.ts
{% endcomment %}

<div class="example-block">
  {{ block.settings.body }}
</div>

{% schema %}
{}
{% endschema %}
```

## Snippet example

Snippets do **not** have a `{% schema %}` block. Inputs are passed as render
arguments and read by name. Variables are scoped to the snippet.

Caller:

```liquid
{% render 'example', heading: 'Hello', count: 3 %}
```

`snippets/example.liquid`:

```liquid
{%- assign heading = heading | default: 'Untitled' -%}
{%- assign count   = count   | default: 1 -%}

<div class="example-snippet">
  <h2>{{ heading }}</h2>
  <p>Repeated {{ count }} time{% if count != 1 %}s{% endif %}.</p>
</div>
```

## Conventions

- Section/block schemas live in `src/schemas/{sections,blocks}/<name>.schema.ts`.
  Filename must match the Liquid filename (without `.schema`).
- Theme-private container blocks are filename-prefixed with `_` (e.g.
  `_group.liquid`, `_divider.liquid`).
- Translation keys live in `locales/en.default.json` (and locale variants).
  Reference them as `t:names.x`, `t:settings.x`, `t:options.x`, etc.
- Settings reach Liquid as `section.settings.<id>` / `block.settings.<id>`.
- Theme-wide settings live in `src/schemas/settings.schema.ts` and compile to
  `config/settings_schema.json`.
